2026-11-14PostgreSQL 복제
항목수정 전수정 후
컨테이너 재시작2,973회0회
기동실패 반복17.1초
ERROR 로그기동마다 발생0건
문제
울산 스탠바이 백엔드가 재시작을 2,973회 반복했습니다.
약 3일 21시간 동안 장애 전환 대상 서버가 없었습니다.
원인
서버 시작 시 실행되는 전적 백필이 SELECT ... FOR UPDATE를 실행했습니다.
스트리밍 복제본은 읽기 전용이라 SQLSTATE 25006으로 실패했습니다.
이 백필은 Flyway와 스케줄러 비활성화 설정과 무관하게 실행됐습니다.
대안
pg_is_in_recovery()는 복제 상태만 판별해 제외했습니다.
스케줄러 설정 연동은 DB 쓰기 가능 여부와 무관하고 승격 전 재기동 시 재발해 제외했습니다.
해결
트랜잭션 시작 직후 SHOW transaction_read_only가 on이면 백필을 건너뜁니다.
로컬 PostgreSQL 17 복제 환경에서 실패를 재현했습니다.
pg_promote() 승격 후 백필이 실행되는 것까지 확인했습니다.
담당
장애 분석, 수정, 회귀 테스트 2건 추가를 담당했습니다.

느린 회선의 웹 스플래시 고정

2026-11-15웹 성능
항목수정 전수정 후

문제
3Mbps 이하 회선에서 웹 첫 화면이 90초 넘게 스플래시 상태로 유지됐습니다.
첫 화면 9,384KB 중 글꼴이 5,388KB(57%)였습니다.
원인
웹 글꼴 로더(expo-font)는 12초가 지나면 실패를 반환합니다.
앱 시작 코드는 글꼴 로딩 완료만 확인해 실패 시 화면에 진입하지 못했습니다.
글꼴 5종을 12초 안에 받으려면 약 3.5Mbps가 필요합니다.
대안
언어 설정과 로그인 복원 대기 가설은 6Mbps에서 정상 동작해 제외했습니다.
Metro 자산으로 woff2를 제공하는 안은 기본 자산 확장자에 woff2가 없어 제외했습니다.
해결
글꼴 오류 시에도 화면에 진입하도록 시작 조건을 바꿨습니다.
글꼴은 woff2 3종, 한글 2,350자 부분 집합으로 축소하고 preload했습니다.
화면별 코드 분할과 HTML 스플래시를 추가했습니다.
측정
Playwright Chrome 390×844, 캐시 끔, 지연 150ms, CPU 4배 감속 조건에서 운영 웹을 측정했습니다.

커뮤니티 글 조회 수 중복과 후속 500 장애

2026-11-06 ~ 07JPA
항목수정 전수정 후
같은 회원 재조회매번 +1변화 없음
로그인 회원 글 상세500200
관련 테스트없음서비스 3건, 통합 1종
문제
같은 회원이 커뮤니티 글을 다시 열 때마다 조회 수가 올랐습니다.
작성자 본인 조회도 포함됐습니다.
서비스를 직접 사용하며 발견했습니다.
1차 해결
조회자당 1행인 조회 기록 표(post_views)를 추가했습니다.
처음 기록될 때만 조회 수를 올리고 작성자, 운영진, 비로그인 조회는 제외합니다.
후속 장애
반영 후 약 20시간 동안 작성자와 재조회 회원의 글 상세가 500을 반환했습니다.
조회 기록 쿼리의 @Modifying(clearAutomatically = true)가 영속성 컨텍스트를 비웠습니다.
먼저 조회한 게시글이 준영속 상태가 되어 지연 로딩에서 LazyInitializationException이 발생했습니다.
해결
조회 기록을 먼저 실행하고 게시글을 조회하도록 순서를 바꿨습니다.
개발 서버에서 수정 전 500, 수정 후 200을 확인하고 통합 테스트를 추가했습니다.
재발 방지
같은 원인의 장애가 2회째였습니다.
clearAutomatically 사용 시 쿼리 전에 조회한 엔티티를 다시 쓰는지 확인하는 리뷰 기준을 장애 기록에 추가했습니다.
